# 수수료 원장 — 데이터 형식과 갱신 순서

대시보드 탭의 '수수료 원장' 묶음(쪽 6개, 앱메모에 xcheck 가 있으면 7개) = 외화 수수료 입금 원장을 읽기 좋게 나눈 화면.
원장 원본은 claude.ai Project 'Back Office 업무연동'의 문서 `claude/외화수수료_원장_2017-2026.csv`
(대화 '수수료 내역 증빙 자료'에서 부가세 영세율 신고자료·회계부 영세율 총괄표·입금결의서·송금명세·인보이스를 대조해 만든 것).
화면에 덧붙이는 설명(기관명·금액이 든 것)은 Project 문서 `claude/외화수수료_원장_앱메모.json` — 공개 저장소 코드에 두지 않는다.
데이터는 암호문 `fees.enc.json` 하나(미팅노트와 같은 비밀번호·salt). 평문(CSV·메모·fees.json)은 스크래치패드에만.

## 갱신 순서 ("수수료 원장 앱에 반영해줘")
1. Project 문서 두 개를 스크래치패드로 받는다(`project_read`; 결과가 글자로 오면 그대로 파일에 쓰지 말고 세션 기록에서 원문을 꺼내 저장 — 숫자 한 자도 바뀌면 안 됨).
2. `python3 scripts/fees_build.py <SP>/외화수수료_원장_2017-2026.csv <SP>/fees.json --notes <SP>/외화수수료_원장_앱메모.json`
   — NO 연속·날짜 형식·신고기간 ↔ 날짜·통화·외화 × 환율 = 원화(±2원)를 확인하고 어긋나면 멈춘다. 출력의 건수·원화 합계·'규칙 밖' 운용사를 본다
   (규칙 밖 이름이 운용사로 묶여야 하면 `GP_RULES` 에 더한다 — 일반 GP·거래처 이름만).
3. `node scripts/vault.mjs encrypt <SP>/fees.json fees.enc.json --salt-from data.enc.json`
4. `git status` 로 fees.enc.json(과 고친 코드)만 → 커밋(`fees: 수수료 원장 MM/DD 기준`, 펀드명·금액 쓰지 말 것) → push. 평문 삭제.
- 대시보드 엑셀(dash.enc.json)을 매일 다시 뽑아도 이 묶음은 그대로다(앱이 두 파일을 따로 열어 붙인다).

## 쪽
| 쪽 | 내용 |
|---|---|
| 원장 요약 | 지표 카드(누적 원화·외화·올해·정기 그룹·증빙 대조·확인 필요) · 연도별 분류 누적 차트 · 연도별 요약 표 · 운용사 상위(전체·연도) · 분류별 · 보수 유형별 · 부서명 변천 |
| 입금 원장 | 516건 전부, 연도 묶음(최근 먼저)·연도별 합계 줄(보이는 행 기준) · 찾기 · 연도·분류·통화·운용사·보수 유형·신고기간·자료 거르기 · 펼치면 인보이스·산정근거·출처(파일·쪽)·비고·회계부 신고액 |
| 운용사별 | 운용사·거래처별 건수·원화·외화(통화별)·첫/마지막 입금 · 펼치면 그 곳 입금 건 전부·연도별 원화 |
| 정기수수료 연도별 | 원장 '정기수수료 그룹'별 연도 칸(외화) · 상태 묶음: 입금 중 / 작년 연말 입금분 / 올해 아직 없음 / 끊김 / 1회 |
| 신고기간별 대사 | 2017-1기 예정 ~ 지금까지 기간마다 건수·원화·USD·EUR·증빙 있는 건·자료 구성·원본 파일 ID · 건 없는 기간 · (앱메모 recon) 대사 상태(대사 완료·대사 불가 등)·원화/USD/EUR 차이·대사 기준·대사 비고 · '신고 대사' 지표 카드 |
| 확인 필요·정정 | 확인 필요 · 추정 값 · 증빙 미확인·미첨부 · 인보이스 매칭 애매 · 회계부 신고액과 다른 건(차이) · 정정·분리 |
| 크로스체크 (앱메모 xcheck 가 있을 때) | 지표 카드(분할 일정·약정내역 대조·인보이스 빈 번호) · 계약·인보이스 분할 일정 대조(판단별 묶음) · 약정내역(KPI 제출 약정) ↔ 원장 산정근거 · 인보이스 번호 공백 · 연내 수령 계획·기타 대조 메모 |

- 분류(화면용 칸): 중개·Custody·상임대리인 = 중개·수탁·대리인 / 정기수수료 그룹이 있거나 Monitoring·Maintenance·Admin·Trailer·Retainer 등 = 관리·모니터링 /
  번역비·리서치·행사 = 용역·기타 / '미확인' 구분 = 미확인 / 그 밖 = 판매 (PA 등). 운용사 = 펀드·내용에 가장 앞에 나온 이름(`GP_RULES`), 없으면 송금인.
- 원장 글자·숫자는 고치지 않는다(화면용 칸은 분류·운용사 둘뿐). 원화는 원장 '원화금액(결의금액)' — 회사 시스템 결의금액 기준.
- 형식(kind "fees"): `{kind, v, generatedAt, source, asof, range[첫, 끝], n, krw, sheets[]}` — sheets 는 dash.json 시트와 같은 모양
  (`name, short, group:"수수료 원장", asofl, view[블록], cols/rows 빈 배열`). 앱 dash.js `addExtra` 가 '실적·KPI' 묶음 바로 뒤에 끼운다.
- 앱메모 형식(2026-11-18 추가): `recon` = {신고기간: {st, nt, bs, rk, ru, re, dk, du, de}}(대사 상태·대사 기준·원화/외화 차이), `xcheck` = {sched[], kpi[], inv[], dup[], plan[], other[]}(크로스체크 쪽). 둘 다 기관명·금액이 들어가므로 Project 문서에만 둔다. 없으면 예전 화면 그대로.
- 점검용 가상 데이터: `tests/fees-fixture.json`(가상만, `fees_build.py` 출력 — 가상 원장 7건 + 가상 recon·xcheck) — smoke 맨 뒤 '수수료 원장' 점검 때만 내보낸다.
